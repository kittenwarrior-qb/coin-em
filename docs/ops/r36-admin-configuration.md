# Restricted admin (local implementation; not deployed)

Owner approves emcoincloud@gmail.com with a separate EmCoin password, not a Gmail password or Google OAuth. No public registration or default credential exists.

## Explicit configuration

- `EMCOIN_ADMIN_PASSWORD_HASH`: owner-provisioned `scrypt-v1` salted hash, generated by `hashAdminPassword` through a private local provisioning flow. Do not pass real passwords in shell arguments, chat, source, build logs or reports. No production password has been generated/configured in this task.
- `EMCOIN_ADMIN_ORIGIN`: exact HTTPS origin, without path/trailing slash/userinfo, admitted only when a password hash exists.
- Missing configuration keeps the admin API disabled. Malformed configured hash/origin fails startup rather than accepting an insecure default.
- Backend must sit behind an owner-controlled HTTPS same-origin reverse proxy with appropriate private-backend exposure controls. No Caddy/VPS configuration was changed here.

## Current API

- `POST /admin/api/login`: JSON email/password, exact Origin and `X-Emcoin-Admin: 1`. Returns success only; session material is exclusively in the Secure/HttpOnly/SameSiteStrict host-only cookie.
- `POST /admin/api/logout`: same Origin/custom-header checks and current cookie; revokes session and clears cookie.
- `GET /admin/api/overview`: current cookie/custom header, no foreign supplied Origin. Returns room id/status/seatcount/revision plus fixed anonymous operational counters only. No nickname/playerID/story/reflection/role/session/token access.
- `POST /admin/api/close-room`: authenticated cookie, exact Origin/custom header and JSON containing only roomId/expectedRevision/UUIDv4 requestId/reason. Reason codes are operator-request, stuck-room, safety; no private free-text reason. Session is rechecked inside the room queue; fresh read plus Redis deletion CAS prevents stale confirmation. Successful response is `{success:true,replayed:boolean}`. Same-ID identical retries read the seven-day primary receipt; conflicting receipt or stale revision409, missing room404, unavailable/uncertain storage503. No automatic mutation retry.
- All responses disable caching. Login JSON is limited4KB; parser errors use fixed scrubbed messages, never echo bodies.

Sessions are single-process, one active admin session,30min monotonic lifetime; relogin/logout/restart revoke prior tokens. A process-wide5attempts/minute cap and one active KDF bound verification costs; this is not a distributed brute-force mitigation or multi-worker session guarantee. No IP/device tracking is introduced.

Operational HTTP counters are fixed-space, volatile, reset at process restart and deliberately not unique users/pageviews/game-action counts. Umami browser injection was removed; no existing Umami deployment/database/service/volume was stopped or deleted.

## UI and deletion receipt

The lazy `/admin` page preserves the existing cartoon/mobile-first430px centered design and button/modal sprites. Password is cleared on submission and never written to localStorage/sessionStorage/logs; privileged metadata is cleared before revalidation/logout. Initial401 offers login;503 truthfully reports unavailable configuration. Requests are bounded to ten seconds, streamed responses to256KiB; timeout is uncertainty, not proof of server rollback. Close has an explicit destructive confirmation, a content-free reason and pending Back/Escape protection. An uncertain manual retry retains the identical request ID/revision/reason; reason editing is disabled after submission. This page has no Coin/role/player-content editor.

Admin close requires Redis even in local development: no JSON-only durable-audit fallback is introduced. The minimal audit (fixed actor, request ID, room ID, reason code, confirmed revision, commit time) is stored inside the seven-day primary deletion marker in the SAME Lua commit as snapshot/index deletion. It contains no room/player/story/Coin/session content and is not a deleted-room backup. It expires with that marker; this is not an indefinite compliance audit log. The local anti-resurrection marker remains minimal. The existing room_closed notification is best-effort after commit and MAY repeat on a verified explicit receipt replay to repair commit/ACK/notification loss; business deletion/audit do not repeat. Production notification also leaves the deleted socket room and refreshes the existing public room list. Client terminal events are scoped to the matching admitted room and matching saved session, so old/duplicate events cannot clear a newer room. No exactly-once socket-delivery claim; a notification failure cannot reverse or repeat deletion.

The checked-in Caddyfile now routes `/admin/api/*` to the backend under the existing emcoin.cloud site; legacy admin.emcoin.cloud redirects to that site's `/admin` rather than Umami. The default production composition no longer starts Umami/Postgres or requires their secrets and injects optional admin hash/origin with disabled empty defaults. These are LOCAL future-configuration edits, not a deployed host change. Existing containers/databases/volumes are untouched, shared ocr2 block is unchanged; no service was contacted/stopped/reloaded. Deployment must verify host authority, same-origin HTTPS route, private backend exposure and correct configured origin. `/admin` remains unavailable when backend config is absent.
